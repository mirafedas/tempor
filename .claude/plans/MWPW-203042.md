# MWPW-203042 — ACOM-DC grouped-variation pznTags migration

## Scope decisions (confirmed with user)

- **DC variants in scope**: all 7 acom-dc templates — `product`, `segment`,
  `mini-compare-chart`, `image`, `headless`, `compare-chart-column`, `pro`.
  Nothing in code gates which DC templates carry `pznTags`; this is a scope
  call, not a derived fact (verified: `pznTags` lives on the single shared
  card CF model, not per-variant — `studio/src/constants.js:155`,
  `studio/src/editors/merch-card-editor.js:156-256`).
- **Market/umbrella tables**: reused unchanged — `LOCALE_TO_COUNTRY_MARKETS`
  and `UMBRELLA_EXPANSIONS` (MU/TM/DZ) apply to `acom-dc` as-is, because
  `getSurfaceLocales('acom-dc')` resolves to the identical `ACOM` locale
  table as `getSurfaceLocales('acom')` (`io/www/src/fragment/locales.js:487`,
  `DEFAULT_LOCALES`).
- **Which rule runs, per surface — CORRECTED, see below**: on `acom-dc`,
  ONLY TYPE 2 (`applyUmbrellaExpansion` — geo expansion: MU→KE/TZ/GH,
  TM→AM/AZ/GE/MD/KZ/KG/TJ/UZ, DZ→OM/MA/LB/JO/IQ/BH, added wherever the
  parent tag is present) runs. TYPE 1 (`applyLocaleToCountry` — locale→country
  rewrite over the 40-market table) does **not** run on `acom-dc` — that
  rewrite is ACOM-only. Both rules keep running on `acom` exactly as today.
- **"/tmp folder" interpretation**: this script family's own gitignored
  `scripts/pzn-tags-locale-to-country/tmp/` directory (matches existing
  convention and the repo-write guard in all three scripts) — not the OS
  `/tmp`. If the OS `/tmp` was actually meant, both surfaces can already use
  `--out /tmp/<file>-<surface>.json` today with zero code changes; flag this
  back if that's what's wanted instead.

## Why reuse is safe (root cause of the "just works" parts)

- `ROOT_PATH`, `getValidLocaleCodes(surface)`, and the `PZN_PATH` regex in
  `pzn-tag-inventory.mjs` are already surface-generic — no `acom` literal
  anywhere in the walk/search/parse logic.
- `pzn-tag-applier.mjs` operates entirely on rows from a report file; it has
  no surface-specific logic at all. **Zero changes needed.**
- `MARKET_TABLE` in `pzn-tag-mapping.mjs` is intentionally pinned to the
  literal `SURFACE = 'acom'` constant when calling `getSurfaceLocales` /
  `getDefaultLocales` — and that's correct to keep, not a bug: it's the
  canonical locale table both surfaces share, so pinning it removes any
  risk of the market table silently diverging if `acom`/`acom-dc` locale
  data ever *does* diverge later. Add a one-line comment recording this
  invariant (see Task 1).

## The one real gap: `IN_SCOPE_VARIANTS` is not surface-aware

Today `pzn-tag-inventory.mjs` imports a single hardcoded
`IN_SCOPE_VARIANTS` array. Running it against `acom-dc` today would
silently filter out every DC card (none of them are named `plans*`). This
is the only functional change required.

## The one real gap: TYPE 1 must not run on acom-dc

`applyBoth()` in `pzn-tag-mapping.mjs` always runs `applyLocaleToCountry`
and conditionally runs `applyUmbrellaExpansion` (gated to the `en_US` DAM
tree, since umbrella children are only registered as `en_US` regions —
`pzn-tag-mapping.mjs:230-235`). For `acom-dc`, `applyLocaleToCountry` must
never run; only the existing `en_US`-tree-gated `applyUmbrellaExpansion`
call applies. Nothing today distinguishes this per surface — it's a new
branch, not a pre-existing bug.

## The one real gap: diff-report output filename collides across surfaces

`pzn-tag-inventory.mjs` already namespaces its default output by surface
(`mas-pzn-tag-inventory-${surface}.json`). `pzn-tag-diff-report.mjs` does
**not** — its default output is the fixed
`mas-pzn-tag-diff-report.json`, so running it for `acom` then `acom-dc`
without an explicit `--out` overwrites the first report. This is the
concrete ask behind "separate files for acom and acom-dc."

## Tasks

### 1. `pzn-tag-mapping.mjs` — make in-scope variants surface-aware

- Replace the single `export const IN_SCOPE_VARIANTS = [...]` with:
  ```js
  export const IN_SCOPE_VARIANTS_BY_SURFACE = {
      acom: ['plans', 'plans-v2', 'plans-students', 'plans-education'],
      'acom-dc': ['product', 'segment', 'mini-compare-chart', 'image', 'headless', 'compare-chart-column', 'pro'],
  };

  export function inScopeVariantsFor(surface) {
      return IN_SCOPE_VARIANTS_BY_SURFACE[surface] ?? [];
  }
  ```
- `IN_SCOPE_VARIANTS` has exactly one consumer (`pzn-tag-inventory.mjs`) —
  confirmed via repo-wide grep — so this is a rename/modify, not an addition
  needing a compat shim.
- Add a short comment above `buildMarketTable()`'s `SURFACE` usage:
  `// Pinned to 'acom': acom-dc shares this exact locale table (see DEFAULT_LOCALES); do not swap in the caller's surface.`
- Add the TYPE-1/TYPE-2 surface gate as data, next to `IN_SCOPE_VARIANTS_BY_SURFACE`:
  ```js
  /** Surfaces where only umbrellaExpansion (TYPE 2 geo expansion) applies — no localeToCountry (TYPE 1) rewrite. */
  export const UMBRELLA_ONLY_SURFACES = ['acom-dc'];
  ```
- Extend `applyBoth`'s options with a `runLocaleToCountry` flag (default
  `true`, named to avoid shadowing the `applyLocaleToCountry` function it
  guards):
  ```js
  export function applyBoth(tags, { locale, applyUmbrella = true, runLocaleToCountry = true } = {}) {
      const localeToCountry = runLocaleToCountry
          ? applyLocaleToCountry(tags, locale)
          : { tags, flags: [], mapped: [], markets: [] };
      const umbrellaExpansion = applyUmbrella
          ? applyUmbrellaExpansion(localeToCountry.tags)
          : { tags: localeToCountry.tags, flags: [], expanded: [], skipped: [] };
      // ...rest unchanged, reads from localeToCountry/umbrellaExpansion as today
  }
  ```

### 2. `pzn-tag-inventory.mjs` — consume the surface-aware variant list

- Swap the `IN_SCOPE_VARIANTS` import for `inScopeVariantsFor`.
- Compute `const inScopeVariantList = inScopeVariantsFor(surface);` right
  after `surface` is resolved from `--surface`.
- Fail fast if empty: `if (!inScopeVariantList.length) { console.error(...); process.exit(1); }`
  (mirrors the existing `--author-host`/token usage-error pattern).
- Replace the two remaining `IN_SCOPE_VARIANTS` references (log line,
  `inventory.variants` field) with `inScopeVariantList`.
- No change to output-file naming — already surface-namespaced.

### 3. `pzn-tag-diff-report.mjs` — gate TYPE 1 off for acom-dc, then namespace the output filename

- In `buildRow`, pass the new flag using `record.surface` (already present
  on every inventory record):
  ```js
  const result = applyBoth(record.pznTags, {
      locale: record.locale,
      applyUmbrella: record.locale === EN_US_TREE,
      runLocaleToCountry: !UMBRELLA_ONLY_SURFACES.includes(record.surface),
  });
  ```
  Import `UMBRELLA_ONLY_SURFACES` alongside the other `pzn-tag-mapping.mjs`
  imports at the top of the file.
- Move `outFile` computation (and its `insideRepo`/`insideOutputDir` guard)
  from module scope into `main()`, after `inventory` is parsed, so the
  default can read `inventory.surface`:
  ```js
  const surfaceSuffix = inventory.surface ? `-${inventory.surface}` : '';
  const outFile = resolve(getFlag('--out') || `${OUTPUT_DIR}/mas-pzn-tag-diff-report${surfaceSuffix}.json`);
  ```
- Keep the `--inventory` presence check at module scope (unrelated to this
  fix, still needs to fail before any file read).
- No other logic in this file is surface-specific — `applyBoth`, flags, and
  grouping all operate per-row already.

### 4. `pzn-tag-applier.mjs` — no code changes

- Confirmed surface-agnostic (operates on report rows only). Running it
  against a DC report is just pointing `--i-have-reviewed` at
  `tmp/mas-pzn-tag-diff-report-acom-dc.json` instead of the acom one.

### 5. `README.md` — document the two surfaces

- Update the scope line to list both surfaces, their variant sets, and
  which rule(s) apply: acom → TYPE 1 + TYPE 2; acom-dc → TYPE 2 only.
- Add acom-dc example commands mirroring the existing acom walkthrough,
  writing to `tmp/mas-pzn-tag-inventory-acom-dc.json` →
  `tmp/mas-pzn-tag-diff-report-acom-dc.json`.
- Note that inventory and diff-report outputs are now namespaced by surface
  by default, so both surfaces' artifacts can coexist in `tmp/` without a
  manual `--out`.
